## 二.基础语法
### 1.常用路由类装饰器
| 装饰器              | HTTP 方法 | 作用           | 常见用途           |
| ---------------- | ------- | ------------ | -------------- |
| `@app.get()`     | GET     | 查询数据         | 获取用户、获取文章列表    |
| `@app.post()`    | POST    | 新增数据         | 登录、注册、新建数据     |
| `@app.put()`     | PUT     | 修改整个资源       | 修改用户全部信息       |
| `@app.patch()`   | PATCH   | 修改部分资源       | 修改昵称、头像等部分字段   |
| `@app.delete()`  | DELETE  | 删除数据         | 删除用户、删除文章      |

## 三.
# FastAPI 三大核心语法

## 1. 请求参数（Request Parameters）
FastAPI 根据参数位置，将请求数据分为三种：

| 类型 | 作用 | 常见场景 | 注意 |
|---|---|---|---|
| Path 参数 | 从 URL 路径中获取数据 | 查询指定 ID 的用户 | 参数必须定义在 URL 中。 |
| Query 参数 | 从 URL 查询参数中获取数据 | 分页、搜索、筛选 | 参数通常用于查询条件。 |
| Body 参数 | 从请求体 JSON 中获取数据 | 注册、登录、提交表单 | 参数通常用于 POST、PUT、PATCH 请求。 |

写法：
```python
#Path 参数：
@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"id": user_id}

#Query 参数：
@app.get("/users")
def get_users(page: int = 1):
    return {"page": page}

#Body 参数：
@app.post("/users")
def create_user(user: User):
    return user
```
核心特点：

- FastAPI 会根据类型注解自动解析参数。
- 自动完成类型转换。
- 参数类型错误时自动返回错误信息。

## 2. 数据模型（Pydantic）
使用 BaseModel 类进行数据校验，通过创建类来描述数据格式。(类似zod)

写法：
```python
from pydantic import BaseModel

class User(BaseModel):
    username: str
    age: int

@app.post("/users")
def create_user(user: User):
    return user
```

FastAPI 自动完成：

- 接收 JSON 数据
- 转换 Python 对象
- 检查字段类型
- 检查必填字段
- 返回错误信息


注意事项：

- 后端接口的数据格式推荐使用 Pydantic 定义。
- 字段需要添加类型注解。
- Pydantic 主要负责数据验证，不负责业务逻辑。

## 3. 路由管理（APIRouter）


@app.get()
@app.post()

但是项目接口越来越多时，所有接口写在 main.py 会导致文件臃肿。

因此使用 APIRouter 将不同业务模块拆分。


核心：

APIRouter

用于创建独立路由。

写法：
```python
#users.py：
from fastapi import APIRouter
router = APIRouter()

@router.get("/users")
def get_users():
    return []


#main.py：
from users import router
app.include_router(router)
```

项目结构：

app/
├── main.py
├── routers/
│   ├── users.py
│   └── orders.py


注意事项：

- 小项目可以直接使用 app 路由。
- 中大型项目推荐使用 APIRouter。
- 不同业务模块建议拆分不同 router。
- APIRouter 本质类似 Express 中的 Router。
