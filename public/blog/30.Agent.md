# Agent开发相关的概念

## 一.什么是 Agent（智能体）

**概念**：Agent 是一个能**自主完成目标**的 AI 系统。会自己**拆解任务 → 调用工具 → 根据结果调整 → 直到做完**。
**核心公式**：`Agent = 大模型（大脑）+ 工具（手）+ 循环（干活方式）+ 运行时（发动机）`，所以agent

## 二.Agent 的三大核心组件

一个 Agent 跑起来，靠三块骨架：**Runtime**（发动机）、**Loop**（循环）、**Tool Calling**（调用外部能力的机制）。

### (1)Agent Runtime（运行时）
**概念**：负责把整个"思考 → 调用 → 执行 → 反馈"过程**真正跑起来的运行环境**。它管理上下文、调度工具、维护状态、处理异常。

>**我自己的理解**：Runtime 就是 Agent 的**发动机/舞台**。模型只管"想"，runtime 负责"把想的东西落地"——拿到模型的工具调用请求，找到对应的工具函数、执行、把结果塞回给模型。没有它，模型再有想法也"动不了"。

### (2)Agent Loop（智能体循环）
**概念**：Agent 不是一次性出结果，而是不断重复 **"思考 → 行动 → 获取结果 → 再思考"** 这个循环，直到任务完成。

这就是经典的 **ReAct 模式**（Reasoning + Acting，先推理再行动）：

```
用户输入
   ↓
[ LLM 思考：判断下一步做什么 ] ──→ 需要外部能力？
   ↑                                  │
   │                             Tool Calling
   │                                  ↓
[ 结果反馈给 LLM 再思考 ] ◀── [ Runtime 执行工具 ]
   │
   └─ 不需要了 → 输出最终答案
```

>大白话：就像你自己**修东西**——看一眼（思考）、拿扳手拧两下（行动）、看看拧好了没（观察结果）、不行再换工具（再思考）。Agent 就是把这个"人工修东西"的过程自动化了。

**循环什么时候停**：LLM 判断任务已完成、不再需要调用工具时，循环结束，输出最终答案。

### (3)Tool / Function Calling（工具调用）
**概念**：Agent 调用外部能力（API、搜索、数据库、执行代码）的机制。

- **Tool（工具）**：把一个函数"暴露"给 LLM，用**名字 + 描述 + 参数结构**告诉它"你有这个能力可用"。工具就是 Agent 的"手"。
- **Function Calling（函数调用）**：LLM 不再输出纯文字，而是输出一段**结构化调用指令**，runtime 解析后执行真实函数，再把结果返回给模型。

```text
工具定义（给 LLM 看的"说明书"）：
{
  "name": "get_weather",
  "description": "查询某城市的天气",
  "parameters": {
    "type": "object",
    "properties": { "city": { "type": "string" } }
  }
}

LLM 返回的调用指令：
{"name": "get_weather", "arguments": {"city": "北京"}}

Runtime 执行真实函数后返回：
{"temp": 28, "desc": "晴"}
```

## 三.开发框架：LangChain 与 LangGraph

### (1)LangChain
**概念**：目前最流行的 LLM 应用开发框架（Python / JS），把开发 LLM 应用需要的组件都封装好了：模型调用、提示词、记忆、工具、Agent。

**特点**：
- **组件化**：像搭积木一样拼装模型、Prompt、工具。
- **生态大**：各种第三方集成都有现成的。
- **缺点**：封装层太厚，"看不到里面在发生什么"，出问题不好排查，所以很多人调侃它"学一半就想换"。

### (2)LangGraph
**概念**：LangChain 团队出的下一代 Agent 框架，专门解决"Agent 循环不可控"的问题。

**核心思想**：把 Agent 的流程画成一张**图（Graph）**——**节点**（Node）是每一步要做的事，**边**（Edge）是流转规则，**状态**（State）在各节点间共享：

```
  开始
   ↓
[ 节点：LLM 思考 ] ←──────┐
   ↓                      │ 还有工具要调用
[ 节点：执行工具 ] ──→ 继续循环
   ↓
[ 节点：输出结果 ] → 结束
```

**和 LangChain 的区别**：

| 对比项 | LangChain | LangGraph |
|---|---|---|
| 定位 | 通用 LLM 应用框架 | 专注 Agent 编排 |
| 循环控制 | 黑盒，交给 AgentExecutor | 白盒，循环画在图里完全可控 |
| 状态管理 | 弱 | 显式 State，可持久化 |
| 复杂场景 | 简单场景够用 | 支持分支、人工介入（Human-in-the-loop）、恢复断点 |

>大白话：**LangChain 是"开箱即用但黑盒"，LangGraph 是"把流程摊开给你看、自己掌控"**。项目要精细控制 Agent 行为，一般选 LangGraph。

## 四.能力封装：Skill（技能）

**概念**：把一类**专业能力打包**（一套指令 + 相关文件/知识），让 Agent 在需要时按需加载。它是一个"即插即用"的技能包。

**和 Tool 的区别**：

| 对比项 | Tool | Skill |
|---|---|---|
| 形态 | 一个可调用的函数 | 一套指令 + 文件的技能包 |
| 触发方式 | LLM 直接调用 | 需要时把内容注入上下文 |
| 用途 | 执行具体操作（查天气、发请求） | 赋予专业领域的"做事的套路"（规范、流程、知识） |
| 例子 | `get_weather()` | "写代码防幻觉"的 skill |

>大白话：Tool 是**借你一把螺丝刀**（拿来就能用）；Skill 是一本**《修车手册》**（告诉你整套流程和注意事项，再配合工具去干活）。Tool 负责"能做什么"，Skill 负责"知道怎么做更专业"。

## 五.低代码平台：Coze 与 Dify

不会写代码也能搭智能体？靠这类**低代码平台**，拖拖拽拽就能做。

### (1)Coze（扣子）
**概念**：字节跳动的智能体开发平台，可视化拖拽搭建 Bot。

**特点**：
- 内置插件市场（新闻、天气、联网搜索等）
- 有知识库（喂自己的资料）、工作流编排
- 一键发布到豆包、抖音、微信等渠道

### (2)Dify
**概念**：开源（可自己部署）的 LLM 应用开发平台。

**特点**：
- 支持 Agent、RAG（知识库）、工作流编排
- 数据自主可控，可私有化部署
- 发布成 API 接入自己的业务系统

**两者对比**：

| 对比项 | Coze（扣子） | Dify |
|---|---|---|
| 厂商 | 字节跳动 | 开源社区 |
| 部署 | 云端 SaaS，开箱即用 | 可自建，数据可控 |
| 发布渠道 | 豆包、抖音、微信等 | API、Web App |
| 适合 | 快速做 Bot 丢到平台 | 想接入自己系统的开发者 |

## 六.总结

- **本质**：Agent = 大模型（大脑）+ 工具（手）+ 循环（干活方式）+ 运行时（发动机）。
- **三件套**：Runtime 把循环跑起来，Loop 决定怎么循环，Tool Calling 提供"动手"的能力。
- **框架**：LangChain 通用但黑盒，LangGraph 可控，适合精细编排。
- **Skill 与 Tool**：Tool 管"能做什么"，Skill 管"知道怎么做专业"。
- **平台**：不会写代码用 Coze / Dify 拖拽搭；要可控、可私有化就选 Dify。

**一句话总结**：智能体就是把"大模型会想 + 工具会做 + 循环会干 + 运行时兜底"组合起来，让 AI 从"回答你"升级成"帮你把事情办完"。
